title: Create your first slop

---

A slop is a focused app and its document in one portable `.slop` package. Start with a working Checklist, then make the interface and data your own.

## Install the tools

Use Bun 1.4.2 or newer. For this release, authoring is supported on macOS. Install the matching hitSlop Mac app in `/Applications` or `~/Applications` for native previews, registration, and document exports. You do not need Node, Swift, Xcode, or a hitSlop repository checkout.

The public CLI workflow is:

```sh
bunx @hitslop/cli init tiny-counter
cd tiny-counter
bun install
bun run dev
```

Alternatively, install the CLI with `bun install -g @hitslop/cli` and run `slop init tiny-counter`. The generated project pins its own CLI and SDK versions; prefer its `bun run` scripts after creation.

:::note[Release availability]
The CLI and SDK must be published together with their matching Mac runtime. Until that package release is available, use the repository's packed-package verification workflow; an older npm package is not a substitute for this v1 SDK.
:::

`init` creates a Checklist project, even if your directory is named `tiny-counter`. The project includes `AGENTS.md` and authoring/design skills in `.agents/skills/`. Ask your agent to read those before editing.

## Understand the source

Read `manifest.json` first. Its slug comes from the directory name. Set your title, description, author, categories, and useful initial window size; keep `runtime` set to `hitslop-v1`.

- `schema.ts` defines document fields; `initial.ts` provides creation-only values.
- `App.svelte` renders and edits the document through typed handles.
- `theme.ts` declares public visual tokens.
- `styles.css` owns layout and component styling; `main.ts` imports it.

The browser preview uses disposable memory. Refreshing resets document state. Restart `bun run dev` after source changes; native persistence is tested in a writable document copy.

## Turn the starter into a counter

Replace the starter's data definition:

```ts title="schema.ts"
import { defineDocument, s } from "@hitslop/document";
export default defineDocument({ title: s.text(), count: s.number() });
```

```ts title="initial.ts"
export default { title: "Tiny Counter", count: 0 };
```

Replace `App.svelte` with:

```svelte title="App.svelte"
<script lang="ts">
  import { Slop, useDocument, bindText } from "@hitslop/document/svelte";
  import schema from "./schema";
  const doc = useDocument(schema);
</script>

<Slop>
  <main class="counter">
    <input aria-label="Counter title" use:bindText={doc.fields.title} />
    <p class="counter-value">{doc.current.count}</p>
    <button onclick={() => doc.fields.count.set(doc.current.count + 1)}>
      Count one
    </button>
  </main>
  {#snippet icon()}<strong class="counter-icon">{doc.current.count}</strong>{/snippet}
  {#snippet exportView()}
    <article class="counter"><h1>{doc.current.title}</h1><p>{doc.current.count}</p></article>
  {/snippet}
</Slop>
```

Give it ordinary CSS, using the starter's declared tokens:

```css title="styles.css"
* { box-sizing: border-box; }
body { background: var(--slop-surface); color: var(--slop-ink); font-family: system-ui; }
.counter { padding: 2rem; text-align: center; }
.counter input { width: 100%; font: inherit; }
.counter-value { font-size: 4rem; font-variant-numeric: tabular-nums; }
.counter button { padding: .8rem 1.2rem; background: var(--slop-accent); color: white; border: 0; border-radius: .5rem; }
.counter button:focus-visible { outline: 3px solid var(--slop-ink); outline-offset: 3px; }
.counter-icon { font-size: 180px; color: var(--slop-accent); }
```

## Build, register, and test persistence

```sh
bun run check
bun run build
bun run register
```

Build emits `dist/tiny-counter.slop` with native artwork. Register installs an immutable template in `~/.hitslop/templates`. In the Mac app, choose **Templates**, select your app, and **Create** a writable copy.

Edit that copy, close immediately after typing, reopen, duplicate it, and export PNG/PDF. Check keyboard focus and a narrower window. Read [styling](/docs/guides/styling/), [data and schemas](/docs/guides/data-and-schemas/), and [icons and exports](/docs/guides/icons-and-exports/) before expanding the app.
