---
title: How .slop files work
description: Source, immutable runtime templates, writable state, and native ownership.
---

A `.slop` is a directory package macOS presents as one document. It carries the interface needed to open it and, once created as a writable document, its local state.

## Source is not the runtime package

Authoring source contains `App.svelte`, `styles.css`, `theme.ts`, `schema.ts`, `initial.ts`, `main.ts`, and a package manifest. Authors define theme defaults once in `theme.ts`, using `defineTheme`. The builder generates two files from those same defaults: `assets/theme.css` declares the `--slop-*` CSS variables, and `assets/theme.json` lets the runtime load the declared tokens and apply owner overrides. You do not maintain either generated file.

```text
theme.ts   ── build ──→ assets/theme.css + assets/theme.json
styles.css ── build ──→ assets/main.css
```

The `assets/` folder in the built package contains compiled output and any bundled static resources. Build produces:

```text
My.slop/
  manifest.json
  app.html
  assets/
    main.js
    main.css
    theme.css
    theme.json
    runtime.json
  state.schema.json
  initial.json
  QuickLook/
    Preview.png
    Icon.png              # optional declared icon
  .agents/skills/hitslop-document/
```

`assets/theme.css` and `assets/theme.json` are immutable build output from `theme.ts`. `runtime.json` identifies the required SDK/Loro release. The authored bundle does not contain its own document engine. The host supplies that pinned runtime.

## A writable copy adds state

```text
state/
  document.sqlite
  writer.lock
  host.lock               # present while a live session advertises itself
  theme.json              # optional owner token overrides
```

Loro in the WebView owns the live document. Swift persists opaque checkpoints and updates in format-1 SQLite. `initial.json` is creation-only data, and `state.schema.json` is a descriptor rather than JSON Schema. There is no editable document JSON projection or `stores/` directory.

The permanent `writer.lock` is the OS ownership lock: never unlink it. `host.lock` is discovery JSON, not ownership. CLI commands route to the live owner's socket or acquire the writer lock and use an engine-only hidden WebView. Headless editing never loads authored `app.html`.

Owner changes go into `state/theme.json`, a separate, bounded token object. It contains overrides, not another copy of the authored theme defaults. Use theme commands rather than editing files underneath a running owner. Duplicating a document preserves its saved content and overrides while creating fresh ownership files.

## Masters and copies

Registered templates and built-in starters remain immutable. **Create** makes a writable copy. Rebuilding or updating a template does not update existing documents. Export uses a live capture or a disposable saved snapshot, not a second writer on the same SQLite file.

Close before moving or copying a document. Keep it on a local filesystem outside iCloud and other synced folders. Packages reject symlink entries, source/dependency caches, and oversized resources. Only `hitslop-v1` is accepted; migrations, schema evolution, and multi-writer local packages are not supported.
