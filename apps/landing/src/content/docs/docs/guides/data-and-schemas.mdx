---
title: Data and media
description: Define a schema-backed document store and optional images or files in a Svelte slop.
---

Use JSON for one compact object graph such as a checklist, settings object, or
small document model. The supported starter connects a root `S.Document` schema
directly to `createDocument`.

## Define the data shape

Author `schema.ts` at the project root. Keep it deterministic because the app
and package builder evaluate it separately.

```ts title="schema.ts"
import * as S from "@hitslop/schema/document";

const checklistSchema = S.Document({
  title: S.String(),
  tasks: S.List(
    S.Object({
      id: S.String(),
      text: S.String(),
      done: S.Boolean(),
    }),
    "id",
  ),
});

export type Checklist = S.Static<typeof checklistSchema>;
export default checklistSchema;
```

`S.List` is an ordered identity list. `S.Array` is replaced as a whole. Put
explicit defaults in root `initial.ts`; validation never coerces values, inserts
defaults, or removes unknown properties. Unknown fields are preserved.

## Open the document store

Import the schema directly. TypeScript infers the state shape, and no generated
file or running development server is required for editor types.

```svelte title="src/App.svelte"
<script lang="ts">
  import { createDocument, Slop } from "@hitslop/svelte";
  import dataSchema from "../schema";
  import initial from "../initial";

  const document = createDocument({ schema: dataSchema, initial });
  const { fields } = document;
</script>

<Slop {document}>
  <!-- editor UI -->
</Slop>
```

`<Slop>` owns host readiness, teardown, error reporting, and capture snippets.
Read frozen `document.data`. There is no writable document proxy.

The explicit initial value must satisfy the schema. It is used when a writable
document has no JSON store yet; builds never ship seed stores.

## Update data from the interface

Write with store verbs. Each call returns `{ ok: true, revision, … }` or
`{ ok: false, error }` — do not throw and `.catch`.

```ts
await document.set(fields.title, "Launch list");
await document.toggle(fields.tasks.item(id).done);
await document.insert(fields.tasks, { text: "Ship the first useful version", done: false });
await document.remove(fields.tasks, id);
await document.move(fields.tasks, id, { before: otherId });
```

`insert` fills the declared identity when you omit it. Use
`transaction(tx => { … })` to batch several commands atomically:

```ts
await document.transaction((tx) => {
  tx.set(fields.tasks.item(id).done, true);
  tx.set(fields.tasks.item(id).archived, true);
});
```

Text fields should use a local draft so typing stays smooth:

```svelte
<textarea {@attach document.text(fields.title)}></textarea>
<textarea {@attach document.text(fields.tasks.item(task.id).text)}></textarea>
```

Successful nonempty mutations expose `result.undo()` while this command is still
the latest revision. Disable the action with `result.canUndo`.

Disable editing until `document.canWrite`. Display `error` and offer `flush()`
when the host reports a failure. Invalid in-memory values are never written.

Browser development uses in-memory JSON and resets on reload. Register the
template and open a writable copy to test persistence, sharing, and external
changes.

## Add named media

Declare optional media on the schema, then bind a store to that path. Storage
is implicit: do not add storage declarations to `manifest.json`.

```ts title="schema.ts"
photo: S.Optional(S.Media()),
attachment: S.Optional(S.Media()),
```

Add those fields to the same `S.Document({ … })` as the rest of the data.

The host writes immutable bytes under `stores/media/<sha256>` and keeps
`{ sha256, mime, bytes, filename? }` in the document.

### Let the user choose an image

`imageStore` displays an immutable bundled fallback until the owner chooses a
replacement. Its reactive `src` switches automatically when the media changes.

```svelte title="src/CoverImage.svelte"
<script lang="ts">
  import { imageStore, type SlopDocument } from "@hitslop/svelte";
  import schema from "../schema";

  let { document }: { document: SlopDocument<typeof schema> } = $props();
  const cover = imageStore(document, document.fields.photo, {
    fallback: "/assets/cover-placeholder.png",
  });
</script>

<img src={cover.src} alt="Document cover" />

<button onclick={() => cover.choose()} disabled={!document.canWrite || cover.isLoading}>
  Choose image
</button>

{#if cover.reference}
  <button onclick={() => void cover.clear()} disabled={!document.canWrite || cover.isLoading}>
    Use default
  </button>
{/if}

{#if cover.error}
  <p role="alert">{cover.error}</p>
{/if}
```

Use `choose()` for the native file picker or `await replace(file)` when your UI
already has a browser `File`, such as from a drop target. `clear()` removes the
document reference and restores the image fallback. Destroy is owned by the
adapter.

If you are not inside `<Slop>`, pass the same `createDocument` instance you
already opened rather than creating a second store.

### Store another known file role

`fileStore` uses the same lifecycle and can suggest accepted file types to the
picker:

```ts
import { fileStore } from "@hitslop/svelte";

const attachment = fileStore(document, fields.attachment, {
  accept: ".pdf,.txt,text/markdown",
});

attachment.choose();
```

The reactive `src` is `null` until a custom file exists. Check `reference`,
`isLoading`, and `error` when drawing the interface.

Both store types provide `choose()`, `replace(file)`, `clear()`, `reload()`,
and `flush()`. Normal close, quit, duplicate, capture, and export already join
registered flush work.

Named media suits stable roles known by the interface. Keep arbitrary lists of
records in JSON and store only their small metadata there.
