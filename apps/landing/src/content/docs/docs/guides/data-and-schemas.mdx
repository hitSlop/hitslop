Loro in the WebView owns the document. The same pinned engine runs in the installed native CLI. Swift stores opaque bytes; it does not interpret your application's fields.

## Define the shape

```ts title="schema.ts"
import { defineDocument, s } from "@hitslop/document";
export default defineDocument({
  title: s.text(),
  budget: s.number(),
  archived: s.boolean(),
  tasks: s.list(s.object({ text: s.text(), done: s.boolean() })),
});
```

The SDK supports text, finite scalar registers, enums, optional scalars, objects, and movable lists of objects. It is a deliberately bounded model; do not use arbitrary arrays, class instances, or non-finite numbers.

```ts title="initial.ts"
export default {
  title: "Weekend", budget: 100, archived: false,
  tasks: [{ text: "Buy groceries", done: false }],
};
```

The builder validates initial values and emits `state.schema.json` and `initial.json`. The former is a document descriptor, not JSON Schema. The latter seeds a new document only; editing it does not rewrite an existing document. Schema evolution and pre-v1 migration are deferred.

## Read snapshots; write through handles

```svelte
<script lang="ts">
  import { Slop, useDocument, bindText } from "@hitslop/document/svelte";
  import schema from "./schema";
  const doc = useDocument(schema);
</script>
<Slop document={doc}>
  <input aria-label="Title" use:bindText={doc.fields.title} />
  <button onclick={() => doc.fields.archived.set(!doc.current.archived)}>
    {doc.current.archived ? "Unarchive" : "Archive"}
  </button>
</Slop>
```

`doc.current` is a read-only snapshot. Do not assign into it. Use handles to set registers or replace text. `bindText` handles input drafts and composition; use it instead of manually copying the whole snapshot on every keystroke. Concurrent IME composition merging is deferred: the last committed whole-text replacement wins.

## Keep row identity stable

Every list row has `$id`. Key Svelte loops and selection state by that ID, not by index:

```ts
const tasks = doc.fields.tasks;
const { id } = tasks.insert({ text: "Book tickets", done: false });
tasks.item(id).done.set(true);
tasks.item(id).text.replace("Book train tickets");
tasks.move(id, { before: anotherTaskId });
tasks.remove(id);
```

Handles preserve identity through reordering. A deleted row is no longer a valid write target. Do not add `$id` manually to creation-only initial values.

## Group changes synchronously

```ts
doc.transaction(tx => {
  tx.fields.title.replace("Ready for the weekend");
  tx.fields.archived.set(false);
});
```

Transactions are synchronous. Do not `await`, schedule later writes, or mutate the live document from inside the callback. A rejected operation discards the entire staged transaction. Accepted transactions publish together; persistence remains asynchronous.

## Save and recover

The host autosaves, and `await doc.flush()` commits drafts and pending writes explicitly. Close, quit, and export flush first. Failed saves retain ownership and offer native retry. Application errors are reported separately from save failures.

CLI reads and mutations use the same interpreter:

```sh
bunx @hitslop/cli schema My.slop
bunx @hitslop/cli get My.slop
bunx @hitslop/cli apply My.slop --op '{"type":"text.replace","path":["title"],"value":"Ready"}'
```

Mutations acknowledge persistence. After an unknown outcome, inspect with `get` before another edit; mutations are never automatically replayed. Raw Loro import/export hooks are internal sharing seams, not the author API. Theme overrides are separate host metadata; see [styling](/docs/guides/styling/).
