---
title: Edit installed documents
description: Inspect schemas, edit through the native owner, and customize declared theme tokens.
---

Create a writable copy before editing. Registered templates are immutable masters.

```sh
bunx @hitslop/cli schema My.slop
bunx @hitslop/cli get My.slop
bunx @hitslop/cli apply My.slop --op '{"type":"text.replace","path":["title"],"value":"Weekend"}'
bunx @hitslop/cli batch My.slop --ops '[{"type":"text.replace","path":["title"],"value":"Ready"}]'
```

Read the descriptor and current state before choosing operations. The CLI prints JSON and reports failures on stderr. Successful mutations acknowledge persistence. If transport fails, run `get` before another edit; do not blindly retry.

The installed app's helper performs edits through the live document socket or an engine-only hidden WebView when closed. It does not load the authored interface for headless edits and never bypasses a busy writer. Installed native editing itself needs no Bun; the `bunx` command is its convenient authoring-CLI entrypoint.

Theme changes use a separate command:

```sh
bunx @hitslop/cli theme get My.slop
bunx @hitslop/cli theme set My.slop --values '{"accent":"#7050ad"}'
bunx @hitslop/cli theme reset My.slop
```

Only declared tokens may be changed. They affect the editor and captures, not application data or layout selectors. Do not edit SQLite, initial values, or theme sidecars underneath a live document. See [data and schemas](/docs/guides/data-and-schemas/) and [styling](/docs/guides/styling/).
