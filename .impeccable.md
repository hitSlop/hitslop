## Design Context

### Users
People who live in local files and talk to an AI coding agent all day. They want a tiny interactive document they can double-click, hand to a friend, and have both the human and the AI edit — without a SaaS, an account, or an export cycle.

### Brand Personality
A card you hold. Associative, tactile, inspectable. Not a dashboard, not a startup landing page, not a “productivity app.”

Three words: **malleable, local, honest.**

### Aesthetic Direction
The **host** is an almost-invisible frame (a HyperCard stage). Personality lives in each `.slop` — every generated document should look like a physical object from its domain (a guidebook page, a diner guest check, a gym clipboard), never a generic SaaS card grid.

Anti-references: Inter-on-white dashboards, cyan-on-dark “AI” gradients, Notion clones, widget-icon-heading card grids, purple glow.

Host chrome: macOS-native, quiet. Documents: print-inspired, paper-tinted, system fonts preferred (local-first — no CDN font dependency required).

### Design Principles
1. The file is the product. If it doesn’t survive `cp`, it doesn’t ship.
2. The host does not impose a look. The document paints itself.
3. Structure is queryable (SQL). The view is HTML. Don’t hide data in the DOM.
4. No Save button. A click is a `COMMIT`.
5. Each document should be unforgettable in a different way. Templates are starters, not a brand system.
