# Engineering contract

The approved [contract-4 cutover](LoroRustCutover.md) is the active development
contract: ABI 2, native Rust owner, storage reader revision 2, SQLite format 2.
Historical contract-3 bytes and records remain sealed; opening them is refused
before storage access, without migration. App/release packaging remains deferred.

Read manifest.json first. Only runtime `hitslop-v1` is accepted. No legacy-format migration. Current development: runtime contract 4/revision 1/SDK 4.0.0. Contract 3 remains sealed historical evidence. Prelaunch contracts 1 and 2 are refused. Preserve sealed runtime bytes and ledger records; later releases follow docs/versioning.md.

- The live document is the shared Rust Loro core owned by Swift. Swift stores checkpoint/update bytes in state/document.sqlite (format 2).
- Validate the durable minimum reader revision before importing state. Each successful append/checkpoint advances it atomically from the host's storage revision; opening or failed writes never advance it. Host-only runtime/Loro upgrades preserve existing app bundles. Record the storage-revision decision for each changed Loro pin.
- One OS writer lock owns a local package. CLI commands route to the live native session or acquire ownership when closed. Never bypass a busy lock or unlink writer.lock.
- Author schema.ts with defineDocument/s from @hitslop/document. state.schema.json is a descriptor, not JSON Schema. initial.json is immutable creation-only data.
- Trial descriptors support text, boolean, object, list(object), and exact integer counters. Other descriptors reject until covered end to end. Read immutable snapshots. Ordinary handles return promises; change(tx => ...) collects synchronous writes and resolves after acceptance plus local publication. flush additionally waits for durability. Preserve $id application identity; derived IDs keep anomalous rows addressable without repairing storage. Counter decrement is increment(-n); anomalous contributions project null plus an issue.

- Never add stores/data.json, persistent JSON mirrors, watchers for JSON reconciliation, a JavaScriptCore document engine, compatibility lenses, or a second document engine. Contract-4 JSON replacement/import is explicitly unsupported during the trial; immutable initial.json still seeds template creation.
- Host and CLI ship one matching runtime. The runtime owns the page and lifecycle and mounts `assets/app.js` through `default.mount(ctx, target)`; apps import nothing from the runtime, never embed Loro or the document implementation, and never call the private Swift bridge or `__slop`. slop dev runs the same Rust core as WASM with disposable state; native WebViews contain no engine.
- Keep TypeBox authoritative for platform manifest/bridge contracts. Manifest readers tolerate unknown metadata with the versioning rule's enum fallbacks; writers stay strict and original manifest bytes are preserved. Generate native contracts with bun run schema:generate; do not edit generated files.
- Runtime packages contain manifest.json, assets/ (including app.js), state.schema.json, initial.json, optional QuickLook images and embedded .agents/skills/hitslop-document guidance. Builds contain no state, stores, source, dependencies or caches.
- Preserve the existing macOS client: TCA Features, Catalog, Host slop windows/hover toolbar, Firebase Analytics/Crashlytics, Sparkle, and NativeCLI. HitSlopDocument supplies the common document engine; HitSlopRuntime integrates it. A runtime rewrite must not replace the client.
- Flush local drafts and document writes before close/export. Failed saves retain ownership and show native retry. Destroy WebViews on close.
- Native code validates package isolation, symlinks, bridge envelopes and resource sizes. Authored code can damage its own document; no independent native semantic validator.
- Active examples are discovered from immediate manifest-bearing directories under examples/slops; bundled.json selects shipped templates. Quick Checklist is the active trial template; other authored sources are archived with provenance. Dedicated fixtures own platform semantics. Each owns its design; use plain CSS and defineTheme tokens. Read examples/slops/PRODUCT.md and docs/guides/authoring.md for visual changes. _vibe is inspiration only.
- CLI: bun slop dev/build/register SOURCE; schema/get/apply/batch/import/compact DOCUMENT. get --snapshot includes a state version. JSON import/replacement explicitly refuses during the contract-4 trial. Runtime masters are immutable; create a writable copy to edit.
- PDF/PNG export is in scope. Collaboration, audio-library import, remote catalog cutover, hosted template publication, undo UI, schema evolution, history pruning, iCloud and other synced folders are deferred.
- The native Swift CLI forwards through the live Unix socket or acquires the native owner when closed, without WebKit. Installed editing needs no Node/Bun. Never load authored app code for headless document operations.
- Catalog discovery combines bundled slops and ~/.hitslop/templates, with manifest-derived categories and Recents. Users unpack external downloads before placing template packages in that folder. Hosted discovery, OpenAPI/Registry, accounts/Auth/App Check, and sharing code live in deferred; Firebase Analytics/Crashlytics stay active.
- Launch includes compatible npm schema/document/CLI packages, published manually after the compatible signed Mac app. CLI versions may advance independently while their exact SDK dependency pins and runtime identity remain compatible. Hosted template publication remains deferred. See docs/guides/releasing.md.
- Reusable attachments are in scope: host-owned immutable blobs in state/attachments, referenced by ordinary Loro fields. Use @hitslop/document/attachments or the native attachment CLI. HTTPS data/media access is allowed; CORS still applies.
- Collaboration readiness: reads are total for decodable state (preserve and flag through issues; never repair on open); validation is strict for local writes; one outbound stream emits every accepted local commit and never re-emits imports; peer IDs are never persisted; writers keep full history; mergeable containers only where concurrent creation means the same field; attachments stay content-addressed; capacity bounds stored checkpoint plus update bytes; ordinary edits append merged updates, counter contributions replay exactly through ordinary updates; failed saves retain live edits and block close/export; explicit discard reloads durable state under the same writer lock and remounts the view. Loro stays in the native owner; WebViews consume immutable publications.

Testing policy and commands live in [testing](testing.md). Agent entrypoint: [AGENTS.md](../AGENTS.md).
